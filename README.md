# Signal

**Find what your users are really saying.**

Signal turns a pile of raw customer feedback (app reviews, support tickets, survey answers) into a short, ranked report:

- the **top problems** users have, ordered by how many unhappy people mention them
- **feature requests** and **what users love**
- **exact counts** and a sentiment split for each theme
- **real quotes** as evidence
- a one-paragraph **executive summary** and a "fix this first" recommendation

What used to take an afternoon of reading takes about a minute.

## Why I built this

As a product manager, I collect far more feedback than I can read. Decisions end up driven by the loudest voice or the most recent ticket rather than by what most users actually say. Signal makes it practical to read *everything* and still get a clear answer.

## How it works (no AI background needed)

1. **Discover:** the AI reads a sample of the feedback and proposes 4–8 specific themes, like "Watch sync failures" rather than "Technical issues".
2. **Tag:** the AI labels every comment with one theme and a sentiment (positive, neutral, negative). Comments that don't fit go into "Other".
3. **Rank:** plain Python counts the labels. The numbers in the report are exact counts, not AI estimates.
4. **Summarize:** the AI writes a short executive summary from those counts.

The AI does the reading. Ordinary code does the counting.

## Try it in 5 minutes

You'll need Python 3.10+ and an Anthropic API key ([get one here](https://console.anthropic.com/)).

```bash
git clone https://github.com/<your-username>/signal.git
cd signal

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env             # then open .env and paste your key
streamlit run app.py
```

Your browser opens the app. Click **Analyze feedback** to run it on the sample data.

> **No key yet?** Click **See an example report** to view a pre-built report for the sample data.

> Prefer not to create a `.env` file? Leave it out and paste your key under **Settings** in the app. It's used for that session only and never saved.

## The sample data: a built-in accuracy check

`sample_data/stride_reviews.csv` contains 150 reviews of **Stride**, a made-up running app. The reviews were generated by `scripts/make_sample_data.py` with these themes deliberately planted:

| Planted theme | Reviews |
|---|---|
| Watch sync failures | 34 |
| Love the coaching plans (praise) | 30 |
| Subscription & billing | 26 |
| Crashes & slowness | 22 |
| GPS accuracy | 16 |
| Feature requests (dark mode, offline, export…) | 14 |
| Vague / off-topic | 8 |

When Signal is working well, its top problems should match this table closely. Theme names will differ and counts may vary by a few, which is the point: you can see for yourself how reliable the AI is.

## The example report

`sample_data/example_report.json` is what **See an example report** shows. The version included was made with a simple keyword-matching stand-in while the app was being built. To replace it with genuine AI output, put your key in `.env` and run:

```bash
python scripts/save_example.py
```

## Use your own feedback

Choose **Upload a CSV**. Any CSV with one comment per row works; Signal guesses which column holds the text, and you can change it. Adding a one-line description of your product improves the theme names.

Signal analyzes up to 500 comments per run to keep costs predictable. You can change `MAX_ROWS` in `synthesizer.py`.

## Cost

A run on the 150 sample reviews makes about 6 small API calls and typically costs a few cents. Choose the Haiku model under **Settings** for the cheapest runs.

## Your API key stays private

- Your key lives in `.env`, which is listed in `.gitignore` and never committed.
- `.env.example` is the shareable template with no real key.
- Before pushing, run `git status` and make sure `.env` is **not** listed.

## Project structure

```
signal/
├── app.py                  # The web interface (Streamlit)
├── synthesizer.py          # The engine: discover → tag → rank → summarize
├── sample_data/
│   ├── stride_reviews.csv  # 150 synthetic reviews with planted themes
│   └── example_report.json # Pre-built report shown without a key
├── scripts/
│   ├── make_sample_data.py # Regenerates the sample data
│   └── save_example.py     # Replaces the example report with a live AI run
├── .streamlit/config.toml  # Theme colors
├── .env.example            # Template for your API key
└── requirements.txt
```
